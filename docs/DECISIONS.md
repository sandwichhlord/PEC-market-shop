P06 — `PaymentProvider` (`src/server/payments/types.ts`): `createCheckout`, `retrieveCheckout` (success-page verification), `cancelCheckout` (expire an open session), `refund`. Stripe-only webhook parsing lives on `StripeProvider.parseWebhook`. The provider is resolved from env on every call (`resolveProviderName`), so tests/E2E switch it via env; the Stripe client is cached per key.
P06 — `PAYMENTS_PROVIDER=stripe` without a key, or an unknown value, is a `PaymentConfigError` → API 503 `PAYMENTS_UNAVAILABLE` (not a silent fallback to mock, which would let people "pay" for free).
P06 — Checkout body sends the cart's `pricePaise` per line; any difference from the current price (tampering or a price change) → 409 `PRICE_CHANGED` with the real prices, and the cart adopts them for the next try. Other refusals: 404 `SHOP_NOT_FOUND` (missing or owner suspended), 409 `SHOP_CLOSED`, `ITEM_UNAVAILABLE` (archived / other shop / unknown id), `OUT_OF_STOCK`. Validation happens inside the order-creating transaction.
P06 — Runtime order numbers: `PEC` + 6 chars from an alphabet without 0/O/1/I (e.g. `PEC7K3QXM`), retried on the rare unique collision. Seed keeps `PEC1001…`.
P06 — Order creation writes the `null → PENDING_PAYMENT` OrderEvent with the customer as actor (not a status change, so it does not go through changeStatus).
P06 — `markOrderPaid` (`src/server/orders/payment.ts`) is the single payment-confirmation path (webhook, success page, mock page): no-op unless the order is PENDING_PAYMENT/PAYMENT_FAILED, re-reads and retries on a concurrent change, and refuses an amount ≠ order total (`AMOUNT_MISMATCH`; the webhook logs it and answers 200 so Stripe stops retrying).
P06 — Stripe Checkout Sessions expire after 30 min (Stripe's minimum) and are created with idempotency key `checkout-<orderId>`; success/cancel URLs carry only `orderId` — the server looks up the session id it stored, never trusting a session id from the URL. Webhooks find the order by session id; `metadata.orderId` is only trusted for an order with no session recorded yet.
P06 — Also handled: `checkout.session.async_payment_succeeded` (same as a paid completion). `charge.refunded` is acknowledged and ignored until refunds exist (P09).
P06 — Cancel URL page (`/checkout/cancel`) closes the Stripe session (best-effort) and marks the order PAYMENT_FAILED; a late Stripe success still places it (PAYMENT_FAILED → PLACED_PAID). Retrying from the kept cart creates a new order — a failed order is never re-opened.
P06 — The mock payment API (`POST /api/payments/mock/[orderId]`) and page 404 unless the mock provider is active, and only the order's customer can use them. "Pay" on a PAYMENT_FAILED order is refused (409 `PAYMENT_CLOSED`); "Pay" twice is a no-op.
P06 — The cart is cleared on the success page only if it still holds the paid order's shop (so a new cart from another shop is not wiped). The cart page shows its own "Clear cart" confirm; the shop page's cart bar keeps its one-tap Clear plus a "View cart" link; the customer top bar gains a cart button with a count.
P06 — Stripe webhook route has no session guard (Stripe calls it); the signature check is its guard and runs before anything is read. It 404s when Stripe is not the provider.
